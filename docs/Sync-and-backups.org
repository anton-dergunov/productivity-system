Your Org files are valuable — this config works to keep them saved, synced
across machines, and recoverable.

* Automatic Git sync
If your vault is a Git repository, this config syncs it in the background: it
commits your changes and pushes/pulls on a timer, so your tasks stay in step
across devices without you running any Git commands.

Syncing is *detected, not configured*. To turn it on for a vault, make that
folder a repository yourself:

#+begin_src bash
cd /path/to/your/vault
git init
git remote add origin git@github.com:you/your-notes.git
#+end_src

If that folder is also in Dropbox, iCloud Drive or another cloud folder, read
[[file:Dropbox-and-git.org][Dropbox & Git together]] before you go any further — there is one setup step
that stops the two syncs from corrupting the repository.

A vault with no =.git= folder is simply left alone, and its indicator says so.
Each vault decides independently, so you can sync work notes and keep a personal
vault local. A vault kept /inside/ a larger repository does not sync either —
syncing it would commit and push that enclosing repository on the vault's
behalf. To override the detection for one vault, set =ps/vault-git-sync= in its
=workspace.org= (see [[file:Vaults.org][Vaults]]).

- A small *mode-line indicator* in the file tree shows sync status. Hover it to
  see when the last successful sync happened (the date is included when it
  wasn't today), and click it to open the sync log.
- Pause and resume with =C-c p s= (Productivity → Sync & Version Control → Git
  Sync Enabled). Resuming resyncs immediately. The entry is greyed out in a
  vault that is not a repository, since there is nothing there to pause.
- For manual control, =C-x g= opens [[https://magit.vc/][Magit]], the full Git interface.

The sync is intentionally quiet and won't commit while you're mid-edit. It also
recovers on its own: if a sync is ever interrupted (for example, your laptop
sleeps mid-pull), the indicator clears the stuck state and resumes by itself.
(Sync is disabled automatically when running the dev launcher — see
[[file:Developing.org][Developing & extending]].)

** When a sync fails
The indicator distinguishes trouble that will pass from trouble that needs you:

| Indicator             | Meaning                                           |
|-----------------------+---------------------------------------------------|
| =✓ Sync=              | The last sync succeeded.                          |
| =↻ Syncing=           | A sync is running right now.                      |
| =⊘ Sync Off=          | This vault is not a repository, or you paused it. |
| =⚠ Conflicted Copies= | The sync worked; a cloud syncer left copies       |
| =⚠ Sync Retrying=     | Out of your hands — it will try again shortly     |
| =⚠ Sync Failed=       | Needs you before syncing can continue             |

/Sync Retrying/ (orange) means the remote server returned an error or the
network is unreachable. Your work is already committed locally and the next
attempt will push it, so there is nothing to do but wait.

/Sync Failed/ (red) means a merge conflict, credentials the remote refused, or
a push rejected because another device got there first. A merge conflict also
pauses syncing and opens the sync log with instructions; resolve it (=C-x g=
for Magit), then re-enable syncing.

/Conflicted Copies/ (orange) is not a Git problem at all: the sync succeeded,
but a cloud syncer left a second copy of a file two machines wrote at once —
=Plans (Your Name's conflicted copy 2026-08-19).org=. Click the indicator for
the list, then see [[file:Dropbox-and-git.org][Dropbox & Git together]] for what to do with it.

Failures are reported *once*, as a single line at the bottom of the frame — a
server outage lasting an hour interrupts you one time, not once a minute. The
indicator carries the state from then on, and its tooltip shows what failed and
how long it has been failing. You are told once more when syncing recovers.

For the full Git output, open the sync log: click the indicator, or Productivity
→ Sync & Version Control → Show Sync Log.

* Auto-save and auto-revert
You rarely need to press save:

- *Auto-save* — Org buffers are written to disk shortly after you stop typing
  (Obsidian-style), so changes are persisted continuously.
- *Auto-revert* — if a file changes on disk (e.g. synced from another device,
  or written by the AI assistant), the open buffer refreshes to match, so you
  never edit a stale copy. This happens silently as long as you have no unsaved
  edits in that buffer. If you /do/ have unsaved edits, Emacs stops and asks
  before discarding them.

** When both sides changed
Sometimes a file changes on disk /while/ you have unsaved edits in it — you
typed on this laptop, and an edit from your phone arrived at the same time.
Neither version is safe to throw away, so the automatic save leaves that file
alone rather than writing your older text over the newer one. Everything else
is still saved as usual.

You are told once, and the file is listed in *Show Files Out of Sync*
(Productivity → Sync & Version Control). From there:

| Key       | What it does                                       |
|-----------+----------------------------------------------------|
| =d=/=RET= | Compare your version with the file, side by side   |
| =m=       | Keep mine — write your version over the file       |
| =r=       | Take the disk version — discard your unsaved edits |
| =g=       | Refresh the list                                   |

Both destructive choices ask first. Clicking a file name compares it, the same
as =d=.

If it happens while you are quitting Emacs, the file is simply left unsaved and
Emacs asks about it in the usual way.

* Sessions
Your set of open files and windows is saved when you quit and restored next
time, so you pick up where you left off. The main window comes back at the size
and position you left it.

Only that one window is restored. If you had extra Emacs windows open (=C-x 5 2=
and the like), they are not reopened — otherwise a window you had long forgotten
about would reappear on the next start, showing a file you never asked for.

* Backups
Emacs keeps versioned backups and auto-save files in dedicated directories
(outside your Org folders), so an accidental change or crash is recoverable.

Blank lines a mobile Org app threw away can be put back from your Git history;
see [[file:Recovering-blank-lines.org][Recovering blank lines]].

* Under the hood / Customize
- Git sync: =lisp/ps-git-sync.el=; behavior is configured in =config.org= →
  /Settings → Git sync/ (=ps/git-sync-interval= and the stuck-sync
  =ps/git-sync-timeout=). Turn it off with the =PS_GIT_SYNC_DISABLE= env var or
  =ps/git-sync-paused=; =ps/git-sync-show-log= opens the log.
  =ps/git-sync-cloud-copy-regexp= (same settings block) is what a cloud
  syncer's leftovers look like; set it to =nil= to stop checking for them.
- Saving Org buffers: =lisp/ps-org-save.el=; settings in =config.org= →
  /Settings → Org saving/ (=ps/org-save-on-focus-loss-idle-threshold=);
  =ps/org-save-show-stale= opens the list of files out of sync.
- Auto-save/revert, sessions, and backups: =config.org= → /Session & Backups/
  and /Org Mode → Behavior → Auto-save .../.
- Conflicted copies of your notes are kept out of the agenda by
  =ps/org-files-exclude-files= (=config.org= → /Settings → Org files/).
